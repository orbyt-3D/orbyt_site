Models and agents

Load real models as parts, then let an AI agent build, edit and render scenes through the orbyt MCP server.

0.9.2 preview. The engine is built and tested; publishing to npm is coming soon, so the install line below will work once the package is live. Names may still change before 1.0.

Models are parts

loadGltf() splits a GLB or glTF file into parts, one per top-level node (a single wrapper root is unwrapped and world transforms are kept). It resolves to { parts, scene, animations, gltf }; pass split: 'whole' to keep the model as one part. Meshopt compression works out of the box, and dracoPath enables Draco.

const { parts } = await loadGltf('/airport.glb');
parts.filter(p => p.name.includes('truck'));   // pick parts by name
renderer.replaceParts(parts);                       // hot-swap the model

The MCP server

orbyt-mcp exposes a live scene to any agent that speaks the Model Context Protocol over stdio. The agent edits the scene with tool calls and asks for rendered frames to check its work.

npx orbyt-mcp --backend gpu --memory 256
FlagValuesNotes
--backendgpu (default) | cpugpu renders with hardware WebGL2 in a headless browser and falls back to cpu if there's no GPU. cpu uses SwiftShader: slower, but works on any machine and in CI.
--memoryMiB, default 256Sets the browser heap, the largest frame (about MiB × 16,384 px, so 256 → 4 MP; bigger requests are downscaled) and the largest model or HDRI file (MiB ÷ 2).
--browserpathChrome, Edge or Chromium executable. Found automatically when omitted.

Rendering through the server needs a Chromium-family browser (Chrome, Edge or Chromium) installed on the machine.

Connect it to an MCP client

With Claude Code:

claude mcp add orbyt -- npx -y -p @orbythq/orbyt@0.9.2 orbyt-mcp --backend gpu --memory 256

Or add it to any client's MCP configuration:

{
  "mcpServers": {
    "orbyt": {
      "command": "npx",
      "args": ["-y", "-p", "@orbythq/orbyt@0.9.2", "orbyt-mcp", "--backend", "gpu", "--memory", "256"]
    }
  }
}

Tools

18 tools ship in 0.9.2 (core); roadmap marks what's planned next.

ToolWhat it doesStatus
create_sceneNew empty scene, or one restored from a file written by save_scene.core
add_primitiveBox, sphere, cylinder, cone, plane, torus, torus knot, capsule or icosahedron, with transform and material.core
load_modelAdd a local .glb/.gltf; replies with mesh count, triangles and size.core
remove_partRemove a part or a light.core
list_partsIds, kinds and positions.core

set_transformAbsolute position, rotation and scale, relative translate, visible.core
set_materialPBR material override (merge or replace); on models it applies to every mesh.core
add_lightDirectional, point or spot light.core
set_cameraEye, target, fov, or auto framing.core
set_environmentHDRI, intensity, background, blur, rotation, ground, sun, bloom, shadows, exposure.core
explode_partsExploded view: pushes parts away from the scene centre.core

render_viewsLabelled 2×2 sheet: front, right, top and perspective (beauty or normals).core

save_sceneSave the editable scene description as JSON.core

A typical agent loop

  1. create_scene or load_model to get something on stage.
  2. list_parts / describe_scene to understand it.
  3. set_material, set_transform, set_camera, set_environment to make changes.
  4. render_frame or render_views to look at the result, then repeat.
  5. bake_frame for a final path-traced still, export_glb or save_scene to keep the work.
